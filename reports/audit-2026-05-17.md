### Note technique — re-indexation full

`scripts/deploy.sh:223` re-indexe systematiquement toute la KB a chaque deploy (`indexer.py` re-embed les 105k docs). Choix "brute force" :
- ✅ Sûr (jamais de drift entre source et embeddings)
- ❌ Couteux : 20-30 min sur 105k docs avec BGE-base (768 dims)
- ❌ Bloque deploy.sh — toute itération doit attendre

**Opti P3** : `indexer.py` calcule un hash stable par document (ex. `sha1(rule_id + content)`), stocke en metadata ChromaDB, et a chaque indexation :
1. Liste les IDs+hashes actuels en collection
2. Compare avec les hashes des sources
3. Upsert seulement les docs avec hash changé, delete les docs absents

Reduirait le re-index typique a quelques centaines de docs (drift quotidien) au lieu de 105k → **deploy.sh < 2 min**.
